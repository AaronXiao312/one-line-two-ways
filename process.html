DEVELOPMENT PROCESS

From a wrong train
to a playable loop.

A living record of the design decisions behind the current prototype.

01

PERSONAL EXPERIENCE

The two-hour detour

The starting point was a real trip to a Burger Festival in west Shanghai. Two Line 10 paths were easy to confuse, and boarding the wrong service caused a long backtrack.

02

DOMAIN INSIGHT

Line number is not enough

The design focus became a specific judgment: compare the train terminal and branch path with the intended destination before boarding.

03

SYSTEM DESIGN

Make the route readable

The brief and system graph describe an observe, judge, act, feedback and adjust loop. The map uses fictional station names so it teaches route-reading without pretending to be an accurate Shanghai map.

04

FIRST WEB PROTOTYPE

Three trips, one skill

This browser prototype turns the loop into three progressively harder trips: read the terminal, notice a branch mismatch, and choose under delay pressure. The interface and interaction are implemented in plain HTML, CSS and JavaScript.

05

NEXT ITERATION

Playtest and refine

Next: ask a classmate to play without coaching, record where route information is misunderstood, and revise the route cues and feedback based on what they find.

This timeline documents the work completed so far. The prototype is published with GitHub Pages; playtest results will be added after a classmate tries it.
